# 01. 프로젝트 개요 — PIN POINT REVIEW

## **프로젝트 명**
Pinpoint (핀포인트 / Pinpoint Review)

-사용자의 쇼핑몰이 가진 문제점을 명확하게 짚어낼 수 있게 도와주는 서비스라는 의미를 내포함.


## **프로젝트 배경**

온라인 쇼핑몰 운영자는 수많은 리뷰를 수집하지만 단순 평점만으로는 고객의 실제 불만 요인이나 개선점을 파악하기 어렵다.  따라서 복합적인 텍스트의 리뷰 속에서 긍정/부정의 핵심 키워드를 자동으로 분류하고, 비즈니스 인사이트로 전환해주는 ai시스템이 필요하다.


## **문제 상황 및 목표 사용자**

**문제 상황**

-평점과 관계없이 리뷰 내용에 불만이 숨어있는 경우 하나하나 확인하지 않으면 놓치기 쉬움

-매출이 감소하거나 반품률이 늘어날 때, 이것이 제품의 문제인지 배송/포장 등의 문제인지 데이터 기반으로 즉시 판단하기 어려움

**목표 사용자**

-네이버 스마트 스토어/쿠팡 등 중소형 셀러

-브랜드 자사몰 마케팅 및 cs 담당자


## **핵심 기능 및 기대 효과**

**핵심 기능**

-회원 가입, 로그인, 로그아웃, 탈퇴 등

-리뷰 수집 + 감성/키워드 분석

-리뷰 통계&대시보드

-키워드 추출&분류

**기대 효과**

-cs 대응 속도 단축: 수백 개의 리뷰를 읽지 않고도 빠른 시간안에 금주 주요 불만 유형 파악 가능

-품질 개선 가이드 제공: 상품 자체의 문제와 유통/포장의 문제를 분리하여 실질적인 운영 개선안 도출


## **프로젝트 범위**

**데이터 수집&데이터 구성**

-쇼핑몰 리뷰 공개 데이터 셋 수집

-정형 데이터(리뷰id, 상품 id, 평점, 작성 일자, 옵션 등) 및 비정형 데이터(리뷰 텍스트) 정제

**데이터 전처리**

-특수 문자 등을 제거하는 텍스트 클리닝 및 감성 분석/키워드 레벨링 파이프라인 구축

-상품 정보, 리뷰 및 감성/키워드 분석 결과, 셀러 정보, 위험 키워드 설정 등 테이블 간 관계 설계 및 ERD 구축

-리뷰 텍스트 및 상품 설명 문서의 임베딩 저장 (※ 8일차 기준: 컬럼만 설계하고 실제 저장·활용은 범위에서 제외 → 아래 '범위에서 제외한 것')

**FastAPI**

-리뷰 답변 등록/조회/수정/삭제

-대시보드용 통계 집계 API(월별 추이, 긍/부정 비율, 키워드 탑10 등)


## **추가적으로 구현해 볼 것(이후)**

-부정적인 리뷰(ex.환불, 교환 등)나 별점이 낮은 리뷰가 들어오면 ‘위험 리뷰’로 자동 분류하여 대시보드 최상단에 카드로 띄워주는 기능

-LLM기반 ‘CS 사과 및 답글 추천 생성기’ : 부정 리뷰를 클릭하면 리뷰를 분석하여 셀러가 바로 복사해서 쓸 수 있는 ‘맞춤형 사과 답글’을 자동으로 추천해주는 기능

-경쟁사 또는 타 상품의 리뷰 비교 분석 기능


## **팀 역할 분담**

| 이름 | 역할 | 담당 |
|---|---|---|

| 김서현 | 디자인 / 프론트엔드 | UI/UX 디자인(Figma), 화면 퍼블리싱, 프론트엔드 로직, 외부 API 연동 |

|---|---|---|
| 감성 분석 모델 학습 · LLM 연동 | 학습 데이터·비용·일정 부담 | 설명 가능한 규칙 기반 분석(`rule-v2`), 템플릿 답글 추천. `analyze_review()` 만 바꾸면 모델로 교체 가능하게 구조화 |

## **10일 일정과 실현 가능성**

| 기간 | 단계 | 산출물 |
|---|---|---|
| 1~3일차 | 기획·요구사항·설계 (Traditional) | `docs/01~06`, Figma 화면 설계 |
| 4~7일차 | AI 와 함께 구현 (AI Assisted) | 백엔드·화면·DB 연동, 테스트, `docs/07~08` |
| 8~10일차 | Agent 활용·품질·배포 (Agentic) | Agent Task, 통합 테스트, 배포, `docs/09~11` |

핵심 기능(회원·상품·리뷰 조회·통계·대시보드)은 Must 로 두고 4~6일차에 먼저 완성, 고도화 기능(답글 추천·상품 비교)은 Could 로 두어 일정이 밀리면 빼도 되게 설계했습니다.
