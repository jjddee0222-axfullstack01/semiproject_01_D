# 07. 테스트 계획서 — PIN POINT REVIEW

7일차(AI Assisted 개발 강화)에 작성하고 9일차(통합 테스트와 품질 개선)에 보완한 테스트 계획입니다.
결과는 [09_test_result.md](09_test_result.md), 테스트 중 발견한 문제는 [08_issue_log.md](08_issue_log.md) 에 기록합니다.

## 1. 목표

| 목표 | 기준 |
|---|---|
| Must 기능(FR-01~08) 정상 동작 | **정상 동작률 100%** (일정표 9일차 기준) |
| Should·Could 기능(FR-09~27) | 자동 테스트로 주요 흐름 확인, 실패 0건 |
| 비기능 요구사항(NFR-01~09) | 보안 규칙(잠금·인증 코드·소유권·블라인드 제외)을 테스트로 확인 |
| 회귀 방지 | 기능을 고칠 때마다 전체 테스트를 다시 실행해 기존 기능이 깨지지 않았는지 확인 |

## 2. 범위

**포함:** 화면(HTML) 라우트, REST API(`/api/v1`), 분석 규칙(`analysis.py`), CSV 적재(`pipeline.py`), DB 제약 조건, 이메일 인증, 시도 횟수 제한, MariaDB 전용 SQL

**제외:** 실제 메일 서버 발송(테스트에서는 발송 함수를 가짜로 바꿔 호출 여부만 확인), 브라우저별 화면 차이, 대량 데이터 성능, LLM 연동(이번 범위 제외)

## 3. 테스트 단계

일정표의 테스트 구조(단위 → API → 통합 → 사용자 시나리오 → 회귀)를 이 프로젝트에 맞춰 나눴습니다.

| 단계 | 무엇을 | 도구 | 파일 / 방법 |
|---|---|---|---|
| 1. 단위 | DB·서버 없이 함수 하나씩: 텍스트 클리닝, 감성·위험도·이슈 유형 규칙, 키워드 추출, 요약, 비밀번호 해시, 입력 검증 | pytest | `test_unit.py`, `test_schemas.py` (`-m unit`) |
| 2. API | `/api/v1` 의 요청·응답, 상태 코드, 오류 형식 `{code, message}`, 소유권(403) | pytest + FastAPI TestClient | `test_api_*.py` (`-m api`) |
| 3. 통합 | 화면 라우트 → DB → 템플릿까지 한 번에: 폼 제출, 리다이렉트, 안내 메시지, 화면에 보이는 숫자 | pytest + TestClient | `test_pages*.py`, `test_models.py`, `test_neutral_sentiment.py`, `test_security_limits.py` (`-m pages`) |
| 4. 사용자 시나리오 | 실제 서버를 띄워 브라우저로 처음부터 끝까지 사용 (4장) | uvicorn + 브라우저 (자동화: Playwright) | 수동 체크리스트 + 자동 실행 |
| 5. 회귀 | 위 1~3단계 전체를 매 커밋 전에 실행 | `python -m pytest` | 전부 통과해야 커밋 (CLAUDE.md) |
| 별도 | MariaDB 호환 | SQLAlchemy MariaDB 방언으로 SQL 생성 확인, 선택적으로 실제 MariaDB 테스트 DB | `test_mariadb_sql.py`, `TEST_DATABASE_URL` |

## 4. 사용자 시나리오

데모 계정 `demo@pinpoint.kr` / `Pinpoint1!` 기준. 각 시나리오의 기대 결과가 모두 맞아야 통과입니다.

| ID | 시나리오 | 단계 | 기대 결과 | 관련 요구사항 |
|---|---|---|---|---|
| S-01 | 회원가입 → 로그인 → 로그아웃 | 가입 화면에서 인증 코드 받기 → 코드 입력 후 가입 → 로그인 → 로그아웃 | 가입 완료 안내, 대시보드 진입, 로그아웃 후 대시보드 접근 시 로그인 화면 | FR-01~03, FR-21 |
| S-02 | 로그인 잠금 | 틀린 비밀번호 5회 → 맞는 비밀번호 | 3·4번째에 남은 횟수 경고, 5번째부터 10분 잠금 안내, 맞는 비밀번호도 거부 | NFR-02 |
| S-03 | 비밀번호 찾기 | 이름·이메일·인증 코드·새 비밀번호·사업자 번호 입력 → 변경 → 새 비밀번호로 로그인 | 변경 후 로그인 화면, 새 비밀번호로 로그인 성공, 정보 5회 불일치 시 10분 잠금 | FR-20, NFR-03 |
| S-04 | 리뷰 CSV 업로드 | 상품 조회 → 양식 내려받기 → CSV 업로드 → 업로드 이력 | 추가·중복·오류 건수 안내, 새 상품 생성, 이력에 기록 | FR-05, FR-23 |
| S-05 | 상품 리뷰 조회·블라인드·복구 | 상품 카드 → 리뷰 필터·정렬 → 악성 리뷰 블라인드(사유 입력) → 블라인드 목록에서 복구 | 블라인드 후 통계에서 제외, 복구 시 다시 포함, 이력 기록 | FR-05~06, NFR-07 |
| S-06 | 통계 확인 | 쇼핑몰 분석 → 기간 변경 | 월별 추이·평균 평점·긍정/중립/부정 비율·키워드 TOP 10 차트 표시, CSV 내려받기 | FR-07, 10, 12, 17, 19, 26 |
| S-07 | CS 답글 처리 | CS챗봇 → 추천 답글 수정 → 복사 → 처리 완료 | 처리한 리뷰는 목록에서 빠지고 답글이 저장됨. 긍정·중립·부정에 맞는 초안 | FR-13~14 |
| S-08 | 위험 키워드 즉시 반영 | 설정 → 위험 키워드 추가 → 대시보드 확인 → 삭제 | 추가 즉시 해당 리뷰가 위험 리뷰가 되고, 삭제하면 원래대로 | FR-18, FR-27 |
| S-09 | 리뷰 목록·상품 비교·처리할 일 | 대시보드 '처리할 일' → 리뷰 목록 필터 → 상품 비교 | 링크로 맞는 필터가 적용된 목록 이동, 두 상품 비교와 차이 요약 | FR-15, FR-22, FR-24 |
| S-10 | 회원 탈퇴 | 설정 → 비밀번호 확인 후 탈퇴 | 탈퇴 완료 화면, 데이터 삭제, 같은 이메일로 재가입 가능 | FR-04 |
| S-11 | 휴대폰 화면 | 폭 390px 에서 주요 화면 열기 | 가로 스크롤 없음, ☰ 메뉴로 사이드바 열림 | FR-25 |
| S-12 | 권한 | 다른 셀러 계정으로 남의 상품 주소 접근 | 화면 404, API 403 | NFR-06 |

## 5. 테스트 환경

| 항목 | 내용 |
|---|---|
| 자동 테스트 DB | 임시 SQLite 파일 (테스트마다 테이블을 새로 만들고 데모 데이터 입력) |
| MariaDB 테스트 | 이름이 `_test` 로 끝나는 테스트 전용 DB 만 허용 (`TEST_DATABASE_URL`) — 운영 DB 보호 |
| 이메일 | 기본은 인증 끔(`EMAIL_VERIFICATION=0`), 인증 테스트에서만 켬. 메일 서버 없이 개발 모드 |
| 시도 제한 기록 | 테스트마다 초기화 (`conftest.py` 의 `fresh_db`) |
| 브라우저 시나리오 | 로컬 uvicorn 서버 + Chromium (데스크톱 1280px, 휴대폰 390px) |

## 6. 실행 방법

```powershell
cd backend
python -m pip install -r requirements-dev.txt   # 처음 한 번
python -m pytest                                # 전체
python -m pytest -m unit                        # 단위만 (api / pages 도 같은 방식)
python -m pytest -k security -v                 # 이름에 security 가 들어간 테스트만
```

## 7. 시작·완료 기준

| 구분 | 기준 |
|---|---|
| 시작 | 기능 구현이 끝나고 해당 기능의 테스트가 작성됨 |
| 완료 | 자동 테스트 전체 통과, 사용자 시나리오 S-01~S-12 통과, Must 기능 정상 동작률 100% |
| 실패 시 | `08_issue_log.md` 에 기록 → 원인 분석 → 수정 → 전체 테스트 재실행(회귀) |

## 8. AI 활용 방식 (7~8일차)

일정표의 AI 활용 사이클(Code → AI Review → Issue 발견 → AI 개선안 → 사람 검토 → 적용 → Test)을 따랐습니다.

- AI 코딩 에이전트가 코드 리뷰·버그 재현·테스트 작성·수정안을 만들고, 사람이 결과를 확인한 뒤 커밋했습니다.
- 에이전트용 규칙은 `CLAUDE.md` 에 두었습니다 (기술 스택 고정, API URL·DB 구조 변경 금지, 작업 후 전체 테스트).
- 버그는 먼저 **실패하는 테스트로 재현**한 뒤 고쳤습니다. 예: 쿠키를 되돌려 인증 코드 시도 횟수를 초기화하는 문제 → `test_old_cookie_replay_cannot_reset_tries`.
