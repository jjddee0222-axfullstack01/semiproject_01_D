## 3. 시스템 구성

FastAPI 한 서버가 Jinja2 화면과 REST API(`/api/v1`)를 함께 제공하고, MariaDB 에 저장합니다. 차트는 화면에서 같은 서버의 통계 API 를 fetch 로 불러 ECharts 로 그립니다. 자세한 내용은 [06_architecture.md](06_architecture.md).

| 결정 | 이유 |
|---|---|
| 세션 테이블 + 쿠키 인증 (JWT 대신) | 화면과 API 가 같은 출처라 쿠키가 가장 단순하고, 로그아웃 즉시 무효화 가능 |
| 블라인드 = 소프트 삭제 | 근거 없는 리뷰를 숨기되 기록은 남기고 복구 가능하게. 모든 집계는 `VISIBLE` 리뷰만 |
| 소유권 기반 권한 | 역할 없이 '내 상품인가'만으로 판단 (API 403, 화면 404) |
| 규칙 기반 분석 + `model_version` | 데이터·비용 부담 없이 설명 가능한 분석. 규칙을 바꾸면 버전을 올려 자동 재분석 |
| 보안 상태는 서버에 저장 | 인증 코드·로그인 잠금을 쿠키에 두면 우회 가능 → 서버 메모리 (`rate_limit.py`) |

## 7. 시연 순서 (발표용, 약 5분)

1. 로그인 → **대시보드 '처리할 일'**: 답글이 필요한 위험 리뷰가 바로 보임
2. **쇼핑몰 분석**: 월별 추이, 긍정/중립/부정 비율, 키워드 TOP 10, 분석 리포트
3. **설정 → 위험 키워드 추가** → 대시보드 위험 리뷰 수가 즉시 늘어남 (셀러 맞춤 분석)
4. **상품별 대시보드**: 악성 리뷰 블라인드 → 통계에서 빠짐 → 복구
5. **CS챗봇**: 추천 답글 수정 → 복사 → 처리 완료
6. **상품 비교**, 휴대폰 화면
7. (보안) 로그인 5회 실패 → 잠금 안내
